# TOOL_ACCEPTANCE.md — Критерии приёмки Tool и слоя Tools

> Приёмка реализации `TOOL_SPEC.md` (по `ADR-0022`). Каждый критерий фальсифицируем: при неверной
> реализации соответствующий тест падает. Идентификаторы используются в именах тестов
> (`tests/test_tool_*.py`, `tests/test_toolbox.py`).
>
> **Статус:** Accepted. **Дата:** 2026-09-15.

---

## 0. Соглашения

- Tools проверяются без LLM, сети, `Run` и оркестратора. «Рассуждение» модели в тестах —
  заранее заданная последовательность `ToolCall`.
- «Tool не запущен» проверяется Tool-шпионом, который записывает каждый полученный вызов.

## 1. Дескриптор и контракт (TLC) — `tests/test_tool_contract.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| TLC-01 | Корректный дескриптор | `ref == "<tool_id>@v<n>"` |
| TLC-02 | `tool_id` пустой / с заглавной / с пробелом / с `@` / с `-` / с цифры / длиннее 64; пустое описание; параметры не кортеж / с повтором имени; версия `0`, `-1`, `bool`, `str`, `float`; параметр с плохим именем, пустым описанием, `kind` не `ToolParameterType`, `required` не `bool` | `InvalidToolDescriptorError` |
| TLC-03 | Изменить дескриптор, параметр, `ToolCall`, `ToolResult`; записать в `ToolResult.data` | `FrozenInstanceError` / `TypeError` |
| TLC-04 | Каждый Tool библиотеки | соответствует `Tool` (mypy --strict); `descriptor` — дескриптор своего модуля; нет `__dict__` |
| TLC-05 | Каталог | ref уникальны; каталог = ровно Tools библиотеки |
| TLC-06 | `ToolResult`: `OK` с ошибкой; `REFUSED`/`FAILED` без ошибки или с данными | `ValueError`; `ok()` копирует данные |

## 2. Границы (TLB) — `tests/test_tool_contract.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| TLB-01 | Импорты всех модулей `tools/` | только разрешённый чистый stdlib, `domain.tool`, `tools.*` — нет skills/agents/application/Run/infrastructure/SDK/`time`/`random`/I/O |
| TLB-02 | Исходники `tools/` | нет обращений `now`/`today`/`utcnow` — часы только внедряются |
| TLB-03 | Сигнатура `invoke` | ровно один positional-only параметр `arguments` |
| TLB-04 | Skill ≠ Tool | у Tools нет `apply`, у Skills нет `invoke`; id каталогов не пересекаются |
| TLB-05 | Модули пакета | все просканированы и импортируются по отдельности |

## 3. Toolbox и выдача (TBX) — `tests/test_toolbox.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| TBX-01 | Выдача подмножества | `descriptors` — только выданные, в порядке выдачи |
| TBX-02 | Вызов доступного, но не выданного / неизвестного / не-строкового имени | `REFUSED`, в ошибке — перечень выданных; Tool не запущен |
| TBX-03 | Ref не доступен; повтор ref; две версии одного `tool_id`; два доступных с одним ref; `grants` — одна строка | `ToolGrantError` при создании |
| TBX-04 | Пустая выдача | нет дескрипторов; любой вызов `REFUSED` |
| TBX-05 | Аргументы не mapping; лишний; нет обязательного; не тот вид (`True` как integer, `"3"` как integer, `1` как boolean) | `REFUSED`; Tool не запущен |
| TBX-06 | Корректный вызов | Tool получает read-only mapping только объявленных аргументов; необязательный можно опустить |
| TBX-07 | Tool бросает `ToolExecutionError` / иное исключение | `FAILED` с причиной / исключение пробрасывается |
| TBX-08 | Успешный вызов | `OK`, данные Tool read-only |
| TBX-09 | Выдача из `Agent.tool_refs` | по умолчанию `()`; Toolbox по `agent.tool_refs` открывает ровно выданное |
| TBX-10 | Шаг рассуждения на реальных Tools | вызов вне выдачи → `REFUSED`, выданный → `OK`; результаты возвращаются в рассуждение по порядку |

## 4. `current_date@v1` (CDT) — `tests/test_tool_current_date.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| CDT-01 | Часы с зоной | `date`, `weekday`, `datetime` из внедрённых часов (секунды, со смещением) |
| CDT-02 | Время около полуночи в зоне `+03:00` | дата — локальная дата часов |
| CDT-03 | Два вызова | часы читаются при каждом вызове |
| CDT-04 | Naive-время | `ToolExecutionError`; через Toolbox — `FAILED` |
| CDT-05 | Лишний аргумент через Toolbox | `REFUSED`; часы не читались |

## 5. `text_metrics@v1` (TXM) — `tests/test_tool_text_metrics.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| TXM-01 | Текст из двух абзацев | счётчики символов, слов, предложений, абзацев |
| TXM-02 | Десятичная точка, `?!`, без точки, одни точки, `…` | правило конца предложения §6 спеки |
| TXM-03 | Абзацы через пустую / пробельную строку; одиночный перенос | правило абзацев |
| TXM-04 | Пустой / пробельный текст | нули |
| TXM-05 | Лимит | `within_limit`, `over_by`, `max_chars` |
| TXM-06 | Без лимита | ключей лимита нет |
| TXM-07 | `max_chars < 1`; нет `text` при прямом вызове | `ToolExecutionError`; через Toolbox — `FAILED` |
| TXM-08 | Повторный вызов | равный результат |

## 6. Иерархия ошибок и Agent

| ID | Сценарий | Ожидание |
|---|---|---|
| TDE-01 | `ToolDomainError` | прямой наследник `DomainError`; `ToolExecutionError` — не `DomainError` (`tests/test_domain_error.py`) |
| AGT-T1 | `Agent.tool_refs` | по умолчанию `()`; неизменяем (`tests/test_agent.py`) |

## 7. Что приёмка НЕ проверяет

Tool-use loop с реальной моделью и перевод дескрипторов в формат провайдера (Этап 7); Tools
поверх адаптеров (после Этапа 6); запись вызовов в трассировку/аналитику (Этап 14);
лингвистическую точность подсчёта предложений (сокращения вроде «т. е.» считаются концом
предложения).
