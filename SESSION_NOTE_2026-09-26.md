# Где мы остановились — 2026-09-26 (лимит сессии)

Не часть иерархии документации (`CLAUDE.md`) — рабочая передаточная записка для следующей сессии,
не источник истины. Удалить после того, как её содержимое разойдётся по очереди задач в
`CLAUDE.md` и коммитам.

## Что сделано за сессию

1. **Витрина (`concept-platform`)** — офис на движке `pixel-agents-hq/pixel-agents`, свой план
   этажа генерируется кодом (`prototype/layout/build-layout.mjs`), мост `bridge/office_bridge.py`
   тянет живые данные из `.omemo/*.sqlite3` фабрики и рисует агентов в офисе по-настоящему.
   Решение и почему — `concept-platform/DECISIONS.md`.

2. **Вендор для генерации сменён с Google на BytePlus** — **ADR-0084**, superseding ADR-0081.
   Причина: у мейнтейнера российский Google-аккаунт, Gemini API недоступен по региону (Mongolia
   есть в списке Google, Russia — нет). BytePlus доступен и по API, и по оплате (монгольская карта,
   auto-billing настроен).

3. **Ключ BytePlus заведён, аккаунт верифицирован как Organization** (в Монголии для BytePlus нет
   тарифа Individual — только Organization, это выяснено практикой, не документацией).

4. **Модель `seedance-1-0-pro-250528` активирована и проверена живым вызовом.** Подтверждено
   API, не сторонним источником:
   - `role: first_frame` / `role: last_frame` — обязательны, без них `400`
   - недоступная ссылка на кадр отклоняется до всякой генерации (`resource download failed` /
     `resource not found`) — это и держало зонд бесплатным почти до конца
   - минимальная ширина кадра — **300px**
   - реальный запрос с двумя валидными кадрами дошёл до `status: succeeded`, вернул `video_url`

## ⚠️ Важно: цена пересчитана и стала хуже

Изначальный расчёт экономии (`~$0.27` за ролик, вдвое дешевле Veo) считался по модели
**`seedance-1-5-pro-251215`**, которая на аккаунте оказалась в статусе **Retiring** — строить на ней
нельзя. Активная модель, которую реально проверили, — **`seedance-1-0-pro-250528`**, и её цена
**вдвое выше** ($0.0025/1K токенов против $0.0012). Пересчитанная стоимость: **~$0.49 за ролик**
вместо ~$0.27. Экономия против Veo сжалась с ~50% до ~11%.

Это не отменяет решение уйти на BytePlus (регион, оплата, Seedream по-прежнему $0.03/кадр) — но
любая экономика/тарифы, посчитанные от старой цифры $0.27, **нужно пересчитать от $0.49**.
Подробности и таблица — `docs/adr/0084-the-generation-department-moves-to-byteplus.md`, раздел
Cost.

## ⚠️ Инцидент в этой же сессии — записан в ADR-0084, не спрятан

Пока проверяли API бесплатными зондами (битые ссылки, чтобы сервер падал до генерации), последний
шаг зонда случайно довёл до **настоящей генерации** — 87 300 токенов, ≈$0.22 по прайсу, покрыто
бесплатной квотой (2M токенов, была нетронута). Отменить не вышло — задача уже была `running`.
Ролик (4с, статичный — оба кадра одинаковые) скачан и показан мейнтейнеру. Полная запись —
раздел «Verification note» в конце ADR-0084.

## Открыто, следующая сессия начинает отсюда

1. **Seedream (картинки) не проверен вообще** — ни разу не вызывался. Список моделей показывает
   `TextToImage` + `ImageToImage` у всех активных версий, но referenceимидж и 9:16 не
   протестированы. Учиться на инциденте выше: **более узкие шаги, стоп-и-спросить** перед любым
   запросом, который предыдущий шаг ещё не доказал безопасным.
2. **Модели для активации:** видео — `ByteDance-Seedance-1.0-pro` уже включена. Картинки — нужно
   активировать что-то из `Dola-Seedream-5.0-pro` / `-flash` / `ByteDance-Seedream-4.5` / `-4.0`
   (то же меню Model activation → Media, поиск "seedream").
3. **`.env` фабрики** (`~/concept/.env`) — сейчас там только `OMEMO_BYTEPLUS_API_KEY`. Не хватает
   `OMEMO_SEEDREAM_IMAGE_MODEL`, `OMEMO_SEEDANCE_VIDEO_MODEL=seedance-1-0-pro-250528`,
   `OMEMO_SEEDANCE_RESOLUTION` — имена по ADR-0084 §4, но код под них (`SeedreamImageGenerator`,
   `SeedanceVideoGenerator`) ещё не написан. Задачи 23.2c / 23.11b в очереди `CLAUDE.md` — сами
   пункты очереди этой сессией ещё не вписаны в `CLAUDE.md`, только упомянуты в ADR.
4. **Docker/n8n:** контейнер `concept-n8n` был остановлен по ходу более ранней сессии — если
   он снова понадобится (текстовая фабрика, задача 22), поднимать через
   `docker compose -f ~/concept/n8n/docker-compose.yml up -d`.
