# Брифы и ревью

Установка Python, окружения и настройки LLM-ролей описаны в [README](../../README.md).
Этот файл описывает подключение Notion и места, где человек принимает решение.

## База брифов в Notion

Создайте интеграцию Notion и предоставьте ей доступ к базе. Укажите в `.env` токен, ID базы
и точные имена её свойств (`OMEMO_NOTION_*`, шаблон в [.env.example](../../.env.example)).

| Свойство | Тип | Назначение |
|---|---|---|
| Готовность, например `Stage` | `status` или `select` | Значение `Ready for production` разрешает производство |
| `Run status` | `rich_text` | Текущий статус, записывается фабрикой |
| `Run id` | `rich_text` | Идентификатор прогона, записывается фабрикой |
| `Review` | `url` | Ссылка на опубликованное ревью |

Названия и значение готовности настраиваются. Текст брифа — содержимое верхнеуровневых
блоков страницы. Неизвестная, неготовая или пустая страница не запускает производство.

```bash
python demo_notion.py <notion-page-id>
```

Результат проходит исследователя, сценариста и QA. Все кандидаты останавливаются на ревью:
`passed` можно одобрить, `flagged` и `failed` требуют решения о доработке или отклонении.
Ошибка вызова QA оставляет прогон в `waiting_qa`; повторная команда повторит проверку.

## Ревью в Notion

Создайте отдельную базу и предоставьте интеграции доступ. Настройте семь
`OMEMO_REVIEW_NOTION_*` переменных из `.env.example`:

| Пример имени | Тип |
|---|---|
| `Name` | `title` |
| `Review id` | `rich_text` |
| `Решение` | `select`: `Одобрено`, `Доработать`, `Отклонено` |
| `Причина` | `rich_text` |
| `Fingerprint` | `rich_text` |

Фабрика создаёт страницу с материалом и замечаниями QA. Человек выбирает решение и при
доработке или отклонении заполняет причину. Повторный запуск той же команды читает решение.
Для нарезки необязательные поля заголовка и описания поста настраиваются отдельно.

## Ревью в Google Docs

Это альтернативное место ревью. Если заданы настройки Notion-ревью, выбирается оно;
иначе настройки `OMEMO_GOOGLE_*` выбирают Google Docs. Неполная настройка выбранного
сервиса приводит к ошибке. Без обоих вариантов ревью хранится только в SQLite.

1. В Google Cloud включите Google Drive API, создайте service account и сохраните его
   JSON-ключ вне репозитория.
2. Создайте папку для документов, предпочтительно на shared drive, и дайте service account
   права редактора. У service account нет собственного дискового пространства Drive.
3. Задайте `OMEMO_GOOGLE_SERVICE_ACCOUNT_FILE` и `OMEMO_GOOGLE_REVIEW_FOLDER_ID`.

В созданном документе заполните `РЕШЕНИЕ:` одним словом: `одобрено`, `доработать` или
`отклонено`; пояснение — после `ПРИЧИНА:`. Не удаляйте маркеры и разделитель
`======== МАТЕРИАЛЫ РЕВЬЮ ========`. Материал ниже разделителя не читается как решение.

## Повторный запуск и доработка

Решение считывается при следующем запуске команды или при обходе ревью через сервис.
В `demo_notion.py` после ID страницы доступны те же флаги `--approve`,
`--request-changes "Инструкции"`, `--reject "Причина"`, что и в `demo_factory.py`.
Явный флаг имеет приоритет над решением из сервиса ревью.

Одобрение завершает прогон только после успешного QA. Доработка и отклонение возвращают
сценарий его автору, создают новую версию и новое ревью. Уже выполненное исследование
не запускается снова. При недоступности сервиса ревью состояние сохраняется до следующего вызова.

База по умолчанию — `.omemo/runs.sqlite3`. Чтобы начать отдельный прогон встроенного демо,
задайте новый путь `OMEMO_RUN_STORE_PATH`; в существующей базе могут быть и другие прогоны.

## Автоматизация

`factory_service.py` использует тот же путь производства:

- `GET /v1/health` — проверка доступности;
- `POST /v1/briefs` с `{"brief_ref": "<page-id>"}` — запуск или продолжение брифа;
- `POST /v1/reviews/sweep` — чтение решений по ожидающим ревью прогонам.

Оба POST требуют `Authorization: Bearer <OMEMO_SERVICE_TOKEN>` и возвращают `202`.
Работа выполняется одним фоновым обработчиком. Очередь находится в памяти; при остановке
сервис завершает текущий бриф и отбрасывает ожидающие вызовы. Сохранённые прогоны остаются в SQLite.

Импорт и настройка двух готовых workflow: [инструкция n8n](../../n8n/README.md).
