# STAGE12_ACCEPTANCE.md — Acceptance Criteria (ROADMAP Этап 12, первый рабочий MVP)

**Версия:** 1.0
**Статус:** Принят
**Дата:** 2026-09-18
**Префикс тестов:** `S12A`
**Решение:** `docs/adr/0051-stage-12-acceptance-and-the-m3-pilot.md`

Производственный путь `STAGE11_ACCEPTANCE.md` **без изменений**: настоящий `ProductionService`
(`build_production_service`) на `127.0.0.1` поверх `BriefProduction` с `build_run_index` —
встроенные Prompt трёх ролей, Skill и Tool Rin, настоящие `AnthropicLLMClient` с подменённым
транспортом под SDK, настоящий `SqliteRunStore` под `BriefStatusReporter`, `InMemoryBriefBoard` в
роли Notion, площадка в роли Google Doc. Каждый запрос строится из закоммиченного воркфлоу n8n
(`n8n_request`), как его прислал бы n8n.

Этап 12 — интеграционный: цепочка `S8A → S9A → S10A → S11A` уже прогоняет весь конвейер, но каждая
проверяет свойства **своего** этапа. Здесь каждый критерий — строка Definition of Done Этапа 12
(`ROADMAP.md`, `PROJECT.md` §2), проверенная на собранной системе и **входом через триггер n8n**
(ADR-0051 §1).

## Acceptance

| ID | Критерий | DoD |
|---|---|---|
| S12A-01 | Обновление готовой страницы → триггер `brief-ready` → Run ждёт человека, кандидат `CANDIDATE`, ссылка на ревью на доске; «одобрено» на площадке → триггер `review-sweep` → кандидат **`APPROVED`**, Run `COMPLETED`, на доске `queued, running, waiting_qa, waiting_human, completed`. | 1 |
| S12A-02 | Пройденный прогон воспроизводим из одной сохранённой строки: снимок нового store равен Run; в нём — бриф как вход первой Task, два `VALID` Output со `schema_ref` каталога, Artifact на каждый Output, Evaluation с вердиктом и `evaluator_ref`, Review с `decided_by`, и Analytics Record на каждый завершённый ход провайдера (provider, model, токены, `Decimal`-стоимость, `prompt_ref`). | 2 |
| S12A-03 | Воспроизведение — не повторное производство: после завершения триггер страницы и sweep (трижды) не вызывают ни одной модели, не пишут на доску и не меняют снимок. | 2 |
| S12A-04 | Без явного Approve наружу не уходит ничего: пока решение не набрано, sweep оставляет кандидата `CANDIDATE` и Run `waiting_human`; «одобрено» при непройденном QA не записывается (review остаётся `PENDING`, артефакт — `CANDIDATE`); `APPROVED` появляется только после явного Approve, прошедшего QA. | 3 |
| S12A-05 | Каждое межагентное сообщение проходит схему: вход Task Leo — payload `VALID` Output Rin; провайдер каждой роли получает tool-схему ровно из объявленных полей (Rin, Leo, QA), а QA — контент кандидата. | 4 |
| S12A-06 | Сообщение, не прошедшее схему, останавливает конвейер: ответ Rin без обязательного поля → Output `INVALID`, Artifact не создан, Task Leo не открыта и Leo не вызван, QA не вызван, Run `FAILED` с `INVALID_OUTPUT_REASON`, на доске последний статус — `failed`, метрики обоих ходов записаны. | 4 |
| S12A-07 | Падение при приёме брифа (процесс умирает после коммита `queued`) не рушит систему: сервис отвечает дальше (`ERROR` в логе), сохранённый Run — `queued` без Task, моделей не было; следующий триггер производит его **с текста брифа с доски** до `waiting_human`. | 5 |
| S12A-08 | Падение при обработке триггера (перечисление ожидающих Runs недоступно) не рушит систему: sweep → `503`, в очередь не поставлено ничего, моделей нет, сохранённый Run не изменён; когда перечисление снова доступно — sweep завершает Run. | 5 |

## Вне критериев

**Milestone M3 этими критериями не закрывается (ADR-0051 §3).** Живой пилот — один настоящий бриф
через настоящие Notion, Google Docs, Anthropic и n8n до одобренного человеком артефакта — остаётся
проверкой оператора: `n8n/README.md` (живой Notion Trigger), ADR-0043 (папка Google Drive для
сервисного аккаунта), `demo_factory.py` (живой вызов провайдера).

Форма файлов n8n — `N8N`; HTTP-граница по отдельности — `SVC`; коммиты и восстановление по шагам —
`SWR`; поведение этапов по отдельности — `S8A`, `S9A`, `S10A`, `S11A`.

## Quality gate

Все S12A-тесты и полный gate (`ruff check`, `ruff format --check`, `mypy --strict`, `pytest`) должны
быть зелёными до коммита.
