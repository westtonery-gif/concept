## Однократное подключение

1. В Google Cloud создайте или выберите проект, включите **YouTube Data API v3**.
2. В **Google Auth Platform** настройте приложение: имя `Content Factory`,
   Audience — External, для режима Testing добавьте свой Google-аккаунт в Test users.
3. В Clients создайте **OAuth client ID → Desktop app**, скачайте JSON.
   API key не нужен. JSON не публикуйте и не вставляйте в чат.
4. В каталоге проекта:

   ```sh
   .venv/bin/python -m pip install -e '.[youtube]'
   .venv/bin/python configure_youtube.py /полный/путь/client_secret.json --handle @tsxmoon-n7s
   ```

5. В системном браузере выберите аккаунт и канал @tsxmoon-n7s и самостоятельно разрешите
   загрузку видео и чтение данных YouTube для проверки канала. Локальный callback
   принимает ответ Google; код авторизации вручную вводить не нужно.

Скрипт сравнит ID канала за @tsxmoon-n7s с каналом, выданным OAuth. При несовпадении
настройка не сохраняется. Токен хранится в `.omemo/youtube-token.json` с правами 0600;
`.omemo/` и `.env` исключены из Git. Режим Testing у Google может требовать повторного
согласия после истечения refresh token; тогда снова запустите подключение.

## Предпросмотр и одобрение

Рядом с MP4 должен лежать TXT с тем же именем и разделами `Название:` и `Описание:`.

```sh
.venv/bin/python post_youtube.py '/полный/путь/clip.unique.mp4' --privacy public
```

Это локальный предпросмотр без сетевого запроса. По умолчанию видимость `private`;
для открытого Shorts нужно явно выбрать и одобрить `public`.

После пользовательского апрува помощник повторяет команду с тем же файлом,
видимостью и `--approve ПОЛНЫЙ_ОТПЕЧАТОК_ПРЕДПРОСМОТРА`. Не подставлять этот флаг
до ответа пользователя. Изменение MP4, TXT, канала или видимости меняет отпечаток.
Этот механизм проверяет неизменность результата; решение пользователя остаётся
отдельным обязательным шагом в чате.

YouTube API принимает обычное видео; выделение его в Shorts зависит от формата и
правил YouTube. При подтверждении API печатается ссылка; обработка, доступность и
ограничения проверяются в Studio. Три текущих пробных клипа не одобрены автоматически:
перед публикацией нужно просмотреть их, включая черновые субтитры.

## Повторы и ошибки

Квитанция отправки сохраняется перед сетевой загрузкой. Внутри загрузки Google SDK
использует resumable upload с ограниченными повторами. После подтверждения сохраняется
ID видео; повтор той же отправки возвращает прежнюю ссылку.

Если процесс завершился или соединение пропало без подтверждения, повторная отправка
блокируется. В этой минимальной версии восстановление сессии после перезапуска не
реализовано: сначала вручную проверить Studio и квитанцию. Не удалять её вслепую.
Изменение текста в TXT не создаёт второй ролик и не редактирует уже загруженный.

Для основного конвейера `OMEMO_POSTING_PROVIDER=youtube` выбирает тот же адаптер.
`demo_clips.py --publish` требует существующего одобрения в review desk; обычная
нарезка без этого флага ничего не отправляет. Для текущего режима согласований в чате
используется `post_youtube.py`, читающий соседний TXT.

## Второй канал: Кик Бутовски

Канал пользователя `@whtprod` подключается отдельным профилем:

```sh
.venv/bin/python configure_youtube.py /Users/tymats/Videos/accounts/youtubeapiserial.json --handle @whtprod --profile whtprod
.venv/bin/python post_youtube.py '/полный/путь/клип.mp4' --profile whtprod --privacy public
```

Профиль сохраняет настройки в `.env.youtube-whtprod`, токен в
`.omemo/youtube-whtprod-token.json`. Подключение без `--profile` остаётся каналом
`@tsxmoon-n7s` для «Отчаянных домохозяек». Назначение материала каналу выбирается
явно через профиль; автоматического распознавания сериала нет. Если профиль не найден,
отправка останавливается. Одобрение привязано к ID канала и не переносится между каналами.
Оба канала требуют предпросмотра и отдельного апрува пользователя перед публикацией.
