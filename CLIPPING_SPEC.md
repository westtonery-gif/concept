# CLIPPING_SPEC.md — Спецификация департамента нарезки

> Технический контракт по `ADR-0053`, `ADR-0055`, `ADR-0056`, `ADR-0058`, `ADR-0059`. Подчинён
> `PROJECT.md` §4 п.11/§12/§18, `ARCHITECTURE.md` §8/§13/§15 и `DOMAIN_MODEL.md` §8
> (PROJECT §17: при конфликте побеждают документы). Приёмка — `CLIPPING_ACCEPTANCE.md`.
>
> **Статус:** Accepted. **Дата:** 2026-09-20.

## 1. Назначение и граница

Второй департамент рядом с фабрикой контента: готовый эпизод сериала (права очищены) →
короткие вертикальные клипы, через **ту же** дисциплину fail-closed QA + Human Review
(`ADR-0018`, `PROJECT.md` §12). Всё добавляется **модулями**; `Run`, `Task`, `Output`,
`Artifact`, `Evaluation`, `HumanReview`, `ContentDirector` и существующие адаптеры **не
меняются** (`PROJECT.md` §4 п.11). Если что-то потребует правки ядра — это сигнал дефекта
архитектуры и отдельный ADR, а не правка по ходу.

**В v1 нет агента-планировщика** (`ADR-0058` §4). Оба режима нарезки — детерминированные шаги
`Workflow`. Единственная роль, где нужна модель, — QA клипа. Департамент **ничего не публикует**:
результат v1 — одобренный файл клипа, который человек выкладывает сам (`ADR-0053` §6).

**Следствие, которое отменяет деталь `ADR-0056` §2:** черновик подписи к посту в v1 **не
создаётся** — его было некому создавать, как только планировщик исчез, а публикации нет, так что
читателя у него тоже нет (`ADR-0022` §2: поля без читателя не заводим). Субтитры, вжигаемые в
клип, берутся из расшифровки детерминированно и подписью не являются.

## 2. Режимы нарезки

`ClipMode` — закрытое перечисление из двух значений (`ADR-0058` §1):

| Режим | Когда | Как режет |
|---|---|---|
| `CHUNK` | сериал ведёт по сути одну линию, главные герои на экране постоянно | подряд идущие куски настроенной длины; каждая граница сдвигается к ближайшей паузе в речи, чтобы рез не пришёлся на середину слова |
| `SCENE` | много главных героев, их сцены **перемешаны** по серии | границы — границы сцен от сервиса понимания видео; подряд идущие сцены сливаются, пока результат короче настроенного максимума; сцена длиннее максимума режется по паузе в речи (правило `CHUNK` для этого одного клипа) |

Режим — **редакционное** свойство на борде, а не вывод алгоритма (`ADR-0055` §2): какой это
сериал, знает редактор. Оба режима дают **один непрерывный интервал** на клип; в v1 ничего не
склеивается (`ADR-0058` §2).

## 3. `EpisodeBoard` (`adapters/episode_board.py`)

Порт, названный по роли, рядом с `BriefBoard`, **не** его расширение (`ADR-0055` §1).

| Метод | Поведение |
|---|---|
| `fetch_episode(episode_ref, /) -> IncomingEpisode \| None` | эпизод, если он на борде и готов к нарезке; `None` — неизвестный, архивный, не готовый и бессодержательный, неразличимо (как `BriefBoard.fetch_brief`) |
| `report_status(episode_ref, /, *, run_id, status: RunStatus) -> None` | показать статус Run на карточке эпизода; повтор безвреден, отказ **никогда** не меняет Run |

`IncomingEpisode(episode_ref, source_ref, mode)` — иммутабельный frozen dataclass, все поля
непустые; `mode` — `ClipMode`. Несёт **редакционное намерение, а не видео**: `source_ref` —
непрозрачная строка, которую разрешает `EpisodeSource`. Длительность клипа, их количество и
платформа **не на борде** — это конфигурация, а не колонка, которую редактор заполняет для каждой
серии (`ADR-0055` §2).

Готовность решает борд, а не агент и не `IF`-узел в n8n (`n8n/README.md`). Ошибка —
`EpisodeBoardError` (техническая, не `DomainError`).

## 4. `EpisodeSource` (`adapters/episode_source.py`)

| Метод | Поведение |
|---|---|
| `locate(source_ref, /) -> LocatedEpisode \| None` | где лежит файл эпизода; `None` — если по этой ссылке ничего нет |

`LocatedEpisode(source_ref, path)` — путь к **локально читаемому** файлу. Первая реализация читает
файловую систему (`ADR-0053` §7). Удалённое хранилище — вторая реализация того же порта, которая
материализует локальную копию: так шаг рендера остаётся простым и не знает про сеть.
Ошибка — `EpisodeSourceError`.

## 5. `FootageIndex` (`adapters/footage_index.py`)

Сервис понимания видео за портом, названным по роли; вендор (Vyra AI, `ADR-0053` §3) живёт в
`infrastructure/` и в контракт не попадает.

| Метод | Поведение |
|---|---|
| `index(located, /) -> IndexedFootage` | разобрать эпизод: длительность, границы сцен, тайминг речи |

`IndexedFootage(duration_ms, scenes: tuple[SceneBreak, ...], speech: tuple[SpeechSpan, ...], skips: tuple[SkipZone, ...] = ())`;
`SkipZone(start_ms, end_ms)` — заставка и титры, которые не покрывает ни один клип (`ADR-0074`): локальный
индекс находит их `fpcalc` (Chromaprint) как общее аудио ≥ 15 с в первой или последней четверти серии
с соседними видеофайлами той же папки (до четырёх); нет соседей — нет зон;
`SceneBreak(at_ms)` в возрастающем порядке; `SpeechSpan(start_ms, end_ms, text)` без наложений.
Ошибка — `FootageIndexError`.

**Индексация занимает минуты и никогда не выполняется внутри шага рассуждения модели**
(`ADR-0053` §4, `ADR-0058` §4): это шаг `Workflow`, а долгая работа живёт на очереди `ADR-0049`.
В v1 к этому порту **не обращается Tool** — обращается шаг `Workflow` через обычный адаптер,
поэтому граница side-effecting Tools (`ADR-0054`) здесь не задействована (`ADR-0058` §4).

## 6. План клипов — чистая функция

Детерминированная функция строит план из `IndexedFootage` и режима. Живёт в
`application/clip_plan.py`, **не** в `skills/`: библиотека Skills импортирует только чистый stdlib
и `domain.skill` (`SKB-01`), а плану нужны типы портов — поэтому он прикладной код, а не Skill.
Чистота от этого не страдает и проверяется отдельно (`CLP-09`).

`plan_clips(indexed, *, episode_ref, mode, chunk_ms, max_ms, pause_tolerance_ms) -> ClipPlan`

`ClipPlan(episode_ref, mode, clips: tuple[PlannedClip, ...])`;
`PlannedClip(index, start_ms, end_ms, transcript, captions)` — `index` с 1, интервалы не
пересекаются и идут по возрастанию. Речь несётся **дважды и намеренно** (`ADR-0062` §2):
`transcript` — плоский текст, его читает QA, потому что судит смысл; `captions` — те же слова
с временами **относительно начала клипа**, их читает рендерер, чтобы рисовать реплику тогда,
когда её произносят. Реплика, пересекающая границу, **обрезается по времени, а не
выбрасывается**: её слова частично звучат в кадре, а терять диалог на каждом резе — ровно то,
что зритель заметит.

| Случай | Результат |
|---|---|
| `CHUNK` | куски по `chunk_ms`; граница сдвигается к ближайшей паузе в речи в пределах допуска, иначе остаётся на месте |
| `SCENE` | склейка **внутри реплики** — не граница (`ADR-0069` §2); подряд идущие сцены сливаются, пока сумма `<= max_ms`; сцена длиннее `max_ms` режется по правилу `CHUNK`, а рез, который сдвиг не вывел из реплики, переносится **на начало этой реплики** |
| `SCENE`, склейки найдены, но все внутри реплик | серия — одна длинная сцена, режется как выше; план **не** пуст |
| эпизод короче одного куска | один клип на весь эпизод |
| есть `skips` (`ADR-0074`) | серия делится на отрезки между зонами, каждый режется по правилу режима отдельно; края зон — границы клипов; отрезок короче 5 с отбрасывается; без зон план прежний |
| нет сцен при `SCENE` | план пуст; Run не падает, клипов просто нет (`CLIPPING_ACCEPTANCE` CLP-06) |

Функция чистая: без ввода-вывода, часов и случайности.

## 7. Рендер и проверка формата

`ClipRenderer` (`adapters/clip_renderer.py`):

| Метод | Поведение |
|---|---|
| `render(request, /) -> RenderedClip` | вырезать интервал, вжечь `captions`, записать файл |

`ClipRenderRequest(located, start_ms, end_ms, captions, destination)`; пустые `captions` —
законно и значит «не вжигать ничего»: клип без речи это обычный клип. Формат файла субтитров
**не в контракте** — это дело адаптера (`ADR-0062` §3). `FfmpegClipRenderer` **вжигает** их
(`ADR-0071`): временный ASS-файл и фильтр `subtitles` (нужен ffmpeg с `libass`); белый жирный
Arial 72 px на холсте 1920×1080 с чёрной обводкой, снизу по центру; фигурные скобки, обратные
слэши и переносы в тексте обезврежены. ffmpeg без фильтра — `ClipRendererError`, а не клип без
субтитров. **Холст (`ADR-0075`):** по умолчанию клип собирается на вертикальном холсте
`OMEMO_CLIP_CANVAS` = `1080x1920` — та же картинка без обрезки по центру, над и под ней чёрные поля,
оставленные под баннеры; субтитры остаются на картинке. `source` сохраняет исходный кадр.


`RenderedClip(path, duration_ms, width, height, container)` — **измерения возвращает тот, кто
рендерил**: он произвёл файл и знает их. Ошибка — `ClipRendererError`.

**Кадр v1 не перекадрируется** (`ADR-0058`, очередь 21.2): рендер сохраняет исходное соотношение
сторон, а чёрные поля добавляет сама платформа. Поэтому проверка формата — про длительность и
техническую пригодность, **не про соотношение сторон**.

**Проверка формата детерминирована и модели не отдаётся** (`ADR-0056` §1). Чистая функция
`check_clip_format(clip, *, limits: ClipFormatLimits) -> tuple[str, ...]`
(`application/clip_format.py`) возвращает нарушения. Клип вне спеки —
**не риск контента**, а рендер, сделавший не то, что ему сказали: это `FAILED` Task со стабильной
причиной (форма `ADR-0033`), а **не** `flagged`-вердикт в очередь человеку.

## 8. Артефакты, QA и гейт

**Один Run на серию** (`ADR-0059`), клипы — его артефакты. Домен не меняется: `open_evaluation`
и `open_human_review` уже адресуют конкретный артефакт, а `CANDIDATE -> APPROVED` сверяется с
одобряющим ревью **этого** артефакта и его последним `PASSED` — тринадцать клипов дают тринадцать
независимых fail-closed гейтов по построению.

- **индексация — свой Task** `index-footage` (`ADR-0068` §2): открыт и закоммичен до вызова
  индекса, успешен с Output `footage-index@v1` — канонический JSON `IndexedFootage`; без
  артефакта. Возобновление перепланирует по записанному индексу, whisper не перезапускается;
- **один Task на клип** — механизм «дописать трассируемый Task», которым уже пользуется доработка
  (`ADR-0032`); у каждого клипа свой Output, Artifact, трасса и повтор;
- содержимое артефакта клипа — канонический JSON: `episode_ref`, `mode`, `start_ms`, `end_ms`,
  `transcript`, `path` отрендеренного файла;
- статус Run покрывает пачку: `RUNNING` → `WAITING_QA` (у всех клипов есть вердикт) →
  `WAITING_HUMAN` (по всем принято решение) → `COMPLETED`; новых рёбер не нужно;
- **клип не решает судьбу Run**: не прошедший QA или отклонённый клип просто не едет; Run падает
  только если сломалось производство;
- **доработка клипа не применима** (`ADR-0059` §6): producer'а, чьё рассуждение можно перезапустить,
  нет. Отклонённый клип не шипится — ни цепочки `SUPERSEDED`, ни цикла доработки.

**QA клипа** — роль `clip_qa_agent@v1` по шаблону `qa_agent` (`ADR-0035`): свой Agent, свой Prompt
`clip-qa-agent`, **без Skills и Tools**, с **неизменной** схемой `qa-verdict@v1` и грамматикой
`ADR-0034`. **С `ADR-0070` (Prompt v3) блокируют только спойлер и клип без содержания** (заставка,
титры, песня); остальные три пункта ниже — подсказки человеку при `passed`. Исходные критерии
(`ADR-0056` §2, `ADR-0058` §3):

1. **самодостаточность** — клип понятен без окружающей серии;
2. **нет осиротевшего панчлайна** — шутка или развязка несёт нужный ей сетап;
3. **нет спойлера** — клип не выдаёт то, что серия раскрывает позже.

Критерий «не резать посреди слова» в список **не входит**: это свойство того, как выбираются
границы (§2, §6), и проверяется детерминированно. На вход QA идёт **расшифровка всей серии** рядом
с расшифровкой клипа — без неё третий критерий нечем применять (`ADR-0056` §3). Доставка —
`ADR-0068`: оценщик — `ContextualArtifactEvaluator`, контекст — `episode_transcript(footage)` из
записанного индекса, по строке на реплику `[start_ms–end_ms] текст`, одинаковый для всех клипов
серии и идущий **перед** клипом. Run без записанного индекса оценить нельзя: ошибка QA, гейт закрыт.

**Текст поста (`ADR-0072`).** Клипу с `passed` роль `clip_post_writer@v1` пишет `title` + `description`
(Task `post-text`) до публикации ревью; ревьюер видит и правит его в свойствах страницы; при
одобрении изменённый текст записывается ещё одним Task'ом `post-text` от `human_reviewer`.
Текст для публикации — последний валидный Output `post-text` артефакта (`latest_post`).

**Автопостинг (`ADR-0073`).** Порт `ClipPublisher` (`adapters/clip_publisher.py`): `submit(PublishRequest)`
идемпотентен по нашему `request_id`, `status(request_id) -> PublishStatus` (`PENDING`/`COMPLETED`/
`FAILED`/`NOT_FOUND` + результат по площадкам). Реализация — `UploadPostPublisher` над upload-post
(`urllib`, multipart вручную, `async_upload`, `Idempotency-Key` = `request_id`). С настроенным
публикатором каждый `APPROVED` клип получает Task `publish-clip` с `request_id` = `<artifact_id>-publish`:
без текста поста — `FAILED NO_POST_TEXT`, ничего не отправлено; иначе Task закоммичен `RUNNING`, затем
**сначала `status`, `submit` только при `NOT_FOUND`**; `COMPLETED` без отказов → Output
`clip-publication@v1` (URL площадок) и `APPROVED → PUBLISHED`; иначе `FAILED PUBLISH_FAILED: …`,
без автоповтора. Run ждёт в `WAITING_HUMAN`, пока у каждого одобренного клипа нет терминальной
публикации.

**Оркестрация — прикладной модуль рядом с `ContentDirector`, а не его правка** (`ADR-0059` §4).
Он обязан сам держать дисциплину коммитов `ADR-0026` §2 и возобновляться, не дублируя
закоммиченный Task или записанный вердикт.

**Публикация ревью по каждому клипу требует своих, по-артефактных функций**: сегодняшние
`pending_review` / `publish_pending_review` / `take_review_decision` берут `pending[-1]` и с
тринадцатью ожидающими ревью адресовали бы одно, молча оставив двенадцать (`ADR-0059` §5).
Существующие функции **не меняются** — на их поведении держится приёмка Этапов 10–12.

## 9. Ошибки

Каждый порт — своя техническая ошибка, не `DomainError`: `EpisodeBoardError`,
`EpisodeSourceError`, `FootageIndexError`, `ClipRendererError`. Адаптеры не меняют `Run`.

## 10. Что вне спецификации

- **Автоматическая публикация** в TikTok / Reels / Shorts — отложена (`ADR-0053` §6).
- **Сборка арки персонажа** одним клипом — отдано сознательно (`ADR-0058` §5); режим по линиям
  вернётся из замороженного `ADR-0057`, если материалу это понадобится.
- **Оценка пикселей** (наезд субтитров на лицо, рез на чёрном кадре) — нужен мультимодальный порт
  (`ADR-0056` «Deferred»).
- **Гранулярность гейта**: один Approve на пачку клипов чанк-режима — **не решено**, владелец
  продукта хочет сначала тест. До теста — один артефакт, один вердикт, один Approve на клип.
- **Максимальная длина клипа** как продуктовое правило и конкретные лимиты платформ — конфигурация.
- **Кэш префикса расшифровки** между вызовами QA одной серии (`ADR-0056` §3).
