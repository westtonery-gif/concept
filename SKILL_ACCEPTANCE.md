# SKILL_ACCEPTANCE.md — Критерии приёмки Skill и библиотеки Skills

> Приёмка реализации `SKILL_SPEC.md` (по `ADR-0021`). Каждый критерий фальсифицируем: при неверной
> реализации соответствующий тест падает. Идентификаторы используются в именах тестов
> (`tests/test_skill_*.py`).
>
> **Статус:** Accepted. **Версия:** 1.1. **Дата:** 2026-09-15.

---

## 0. Соглашения

- Skills проверяются изолированно: без агентов, оркестратора, `Run`, моков, сети и LLM.

## 1. Дескриптор и контракт (SKC) — `tests/test_skill_contract.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| SKC-01 | Корректный дескриптор | `ref == "<skill_id>@v<n>"` |
| SKC-02 | Пустые/некорректные `skill_id` (пробел, `@`), `name`, `purpose`; версия `0`, `-1`, `bool`, `str`, `float` | `InvalidSkillDescriptorError` |
| SKC-03 | Изменить дескриптор, вход или выход | `FrozenInstanceError` |
| SKC-04 | Каждый Skill библиотеки | соответствует `Skill[In, Out]` (mypy --strict), `descriptor` — дескриптор своего модуля, без состояния (`__slots__ == ()`) |
| SKC-05 | Каталог | ref уникальны; каталог = ровно Skills библиотеки |

## 2. Границы (SKB) — `tests/test_skill_contract.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| SKB-01 | Импорты всех модулей `skills/` | только чистый stdlib, `domain.skill`, `skills.*` — нет agents/application/Run/infrastructure/часов/случайности/I/O |
| SKB-02 | Сигнатура `apply` | ровно один positional-only параметр `skill_input` |
| SKB-03 | Повторный вызов, новый экземпляр | равный результат |

## 3. `segment_text@v1` (SEG) — `tests/test_skill_segment_text.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| SEG-01 | Короткий текст | один сегмент |
| SEG-02 | Несколько предложений | жадная упаковка целых предложений |
| SEG-03 | Абзацы (в т. ч. «пустая» строка с пробелами) | не сливаются |
| SEG-04 | Предложение длиннее лимита | упаковка по словам |
| SEG-05 | Слово длиннее лимита | нарезка по `max_chars` |
| SEG-06 | Лимиты 1…59 на смешанном тексте | каждый сегмент 1…`max_chars`, обрезан, без двойных пробелов; непробельные символы сохранены по порядку |
| SEG-07 | Пустой/пробельный текст | `()` |
| SEG-08 | Смешанные пробелы | нормализованы до одного пробела |
| SEG-09 | `max_chars` `0`/`<0`/`bool`/`float`; `text` не `str` | `InvalidSkillInputError` |

## 4. `normalize_terminology@v1` (TRM) — `tests/test_skill_normalize_terminology.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| TRM-01 | Вариант в разном регистре | заменён; отчёт с числом замен |
| TRM-02 | Вариант внутри другого слова | не заменяется |
| TRM-03 | Пересекающиеся варианты, короткий первым в глоссарии | побеждает длинный |
| TRM-04 | Канон одного варианта — вариант другого | повторной замены нет |
| TRM-05 | Перенос строки внутри варианта | совпадение |
| TRM-06 | Уже каноничное вхождение | не считается заменой |
| TRM-07 | Пустой глоссарий | текст без изменений, отчёт пуст |
| TRM-08 | Пустые `variant`/`canonical`; дубли без учёта регистра/пробелов; `text` не `str` | `InvalidSkillInputError` |
| TRM-09 | Отчёт | в порядке глоссария, только использованные записи |

## 5. `check_required_elements@v1` (REQ) — `tests/test_skill_required_elements.py`

| ID | Сценарий | Ожидание |
|---|---|---|
| REQ-01 | Все элементы есть | `complete`; `present` в порядке входа |
| REQ-02 | Элементов нет | `missing` в порядке входа; не `complete` |
| REQ-03 | Найдена одна из фраз | элемент присутствует |
| REQ-04 | Другой регистр, переносы/лишние пробелы | совпадение |
| REQ-05 | Фраза внутри другого слова | не совпадает |
| REQ-06 | Пустой набор; пустой/повторный `element_id`; нет фраз; пустая фраза; `text` не `str` | `InvalidSkillInputError` |
| REQ-07 | Фраза со спецсимволами (`18+`, `a.b`) | литерал, не regex |

## 6. Иерархия ошибок (SDE)

| ID | Сценарий | Ожидание |
|---|---|---|
| SDE-01 | `SkillDomainError` | прямой наследник `DomainError` (`tests/test_domain_error.py`) |

## 7. Первый потребитель (SCI) — `tests/test_skill_invocation.py`, role/integration tests

| ID | Сценарий | Ожидание |
|---|---|---|
| SCI-01 | Agent без Skills / Rin | по умолчанию `skill_refs == ()`; Rin объявляет ровно `normalize_terminology@v1` |
| SCI-02 | Объявленные refs и invocation-binding'и не совпадают или переставлены | `CompositionError` до вызова модели |
| SCI-03 | Executor-decorator получает строковый вход | invocation'ы применяются в объявленном порядке, delegate вызван ровно один раз, `ExecutionResult` не изменён |
| SCI-04 | Реальный keyless run Rin с `"омемо"` во входе | модель получает `"OMEMO"`, а Task хранит исходный вход |
| SCI-05 | Resume повторяет незавершённый Task | чистый Skill снова применяется к сохранённому исходному входу перед единственным повторным вызовом delegate |
| SCI-06 | Agent без `skill_refs` | Composition Root оставляет bare executor; прежний путь не меняется |

## 8. Что приёмка НЕ проверяет

Post-execution Skills и policy над их отчётами; персистентный trace invocation'ов; статус
`Deprecated`; Skills поверх Tools/Adapters; лингвистическое качество сегментации (сокращения вроде
«т. е.» могут резать предложение — лимит и сохранность символов при этом соблюдаются).
